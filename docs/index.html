Getting started with Studio

Studio is where you build your web app with Claude, one feature at a time. You describe what you want in plain words, watch it appear, and keep it or throw it away. Every version is saved for you, so there's nothing to set up and nothing you can break for good.

1. Install Studio (once)

You don't need anything set up first: no GitHub account, no developer tools. Open the Terminal app (press ⌘ Space, type Terminal, press Return), paste this line and press Return:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/KingTenet/studio/main/bootstrap.sh)"

It takes a while, about 15–30 minutes the first time. Along the way:

  • It asks for your Mac's password, sometimes more than once. Nothing shows on screen as you type. That's normal; press Return when you've typed it.
  • Your browser opens to log into GitHub. GitHub is where your app is backed up, privately. If you don't have an account yet, you can make one there and then. Terminal shows a code to type into the page.
  • Your browser opens to log into Claude with your own Claude account.
  • It asks for your name and email, which go on your app's saved versions.

If it stops part way, it says what went wrong. Fix that, paste the same line again, and it carries on from where it stopped. Steps that are already done are skipped.

2. Make your app

When the install says All set, open a new Terminal window (⌘ N), so it knows the studio command. Then fill this in and copy the command it makes:

Lowercase letters, numbers and dashes, such as writing-planner. It's the name of the app's folder and its backup on GitHub.

Their GitHub username. They get an invitation to your app's private backup, so they can look at it with you.

studio new my-app

Paste it into the new Terminal window and press Return. Studio makes your app, backs it up privately on GitHub and puts it in Applications. That's the real app, for using it day to day (see Using your app for real below). Then type studio up to start building.

Open it

Open the Terminal app, type this and press Return. After installing, it's the only command you need.

studio upStudio opens in your browser at localhost:4000.

If Studio is already running, typing it again just brings the page back. You can close the browser tab whenever you like; your work carries on where you left it.

What's on the screen

Left: Feature and Versions
What you're building now and each step Claude has saved, with Keep and Discard. Below that, every version you've kept so far.
Middle: your app
Your app, running live. It changes as Claude works, so you can try things straight away. The Artifacts tab shows plans and explanations Claude writes for you. On Draw you can sketch something and send the sketch to Claude.
Right: the chat
Talk to Claude here. The switch above the message box says what kind of message you're sending.

Three kinds of message

Ask

A question. Claude looks and answers, and changes nothing.

“Where do my deadlines get saved?”

Plan

Talk an idea through first. Claude asks you a few questions, one at a time, each with a suggested answer, then shows you a plan. Nothing changes yet.

“I'd like a weekly planner.”

Build

Make the change. Claude edits the app, and you see it happen in the middle.

“Make the deadlines red when they're this week.”

A plan comes with a Build this button. Press it when you're happy, and Claude builds exactly what you agreed.

How a feature works

A feature is one thing you want your app to do, like "weekly planner". When you send your first Plan or Build message, Studio asks you to name the feature. After that it saves your work by itself.

Go back to here
Next to any earlier checkpoint. Use it if Claude went the wrong way: the app and its test data go back to that moment. Changed your mind? Bring them back works until you send your next message.
Keep
When the feature works the way you want. Studio checks the app still works properly, then saves the feature as the next version, with a short note on what it does. If the check finds a problem, ask Claude to fix it. You can also choose keep anyway.
Discard
When you'd rather not have it. The app goes back to your last version, as if the feature never happened.

After Keep or Discard, the chat starts afresh for your next feature. Work on one feature at a time.

Talking instead of typing

Click the ear by the message box and just speak. Studio writes down what you say. Press Space to send it, or the mic to edit the text first. Esc throws it away.

Your versions

Every feature you keep becomes a version: v1, v2, v3 and so on. They're listed on the left, newest first. Nothing in the list is ever lost.

Preview
Look at an old version in the middle for a while. back to latest returns you to where you were.
Restore
Bring an old version back for good. It's saved as a new version on top, so the later versions stay in the list and you can change your mind again.

Using your app for real

The app in the middle of Studio is your workshop. Its data is for trying things out, and Discard or Go back can rewind it. Keep your real calls, deadlines and plans in the real app:

  • Open your app from Applications (it has your app's name), or drag it into the Dock. It opens in the browser at localhost:5001.
  • It runs the newest version you kept, with its own data. Nothing you do in Studio touches that data.
  • After you keep a new version, the next time you open the app it updates itself, and saves a backup copy of your data first.

You don't need Studio running to use your app. Studio is only for changing it.

Another app

Studio works on one app at a time. To start a second one, type studio new and its name in Terminal, for example studio new recipe-box. Studio makes it, switches to it, and puts it in Applications too.

To go back to the first, type studio switch and its name, for example studio switch my-app. Each app keeps its own versions, its own feature in progress and its own chat with Claude, so you pick up where you left off.

If something goes wrong

The app shows an error
Press Ask Claude to fix this. Claude gets the error and fixes it.
“Reconnected”
Claude had stopped and was started again where it left off. Carry on.
“not backed up”
By your app's name: your latest work hasn't reached GitHub yet. Studio keeps trying by itself, usually because the internet was down.
Buttons wait
Keep, Discard and the others wait while Claude is working, so nothing gets mixed up. Let it finish.
Not sure?
Switch to Ask and ask Claude, in your own words. Your app is also saved privately on GitHub, so the person who set Studio up can always look at it with you.

Your first ten minutes

  1. Type studio up in Terminal. The Getting started page appears in the middle, with three example ideas.
  2. Open See an example: a todo list and add a couple of items, to get a feel for the app.
  3. Switch to Plan and paste the first example, “Your app”, into the chat. Name the feature, answer Claude's questions, and read the plan.
  4. Press Build this and watch it appear. Ask for changes until you like it.
  5. Press Keep. That's version v3, and your app now opens from Applications.
